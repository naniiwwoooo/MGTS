# МГТС · веб-дашборд

Из корня проекта установите зависимости и запустите локальный сервер.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-dev.txt -r frontend/requirements.txt
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Для существующего окружения пропустите создание `.venv`. Откройте
[дашборд](http://127.0.0.1:8000) или [описание API](http://127.0.0.1:8000/docs).
Для запуска только новой версии достаточно `backend/requirements.txt`.

FastAPI отдаёт интерфейс из `frontend/web` и JSON из `/api`. Исходные
Excel-файлы остаются в `data`. Streamlit можно запустить отдельно по
[его инструкции](../frontend/README.md).

## ИИ-выводы

Настройки провайдера берутся из переменных окружения и `llm/.env`.
Названия параметров приведены в `llm/.env.example`. Ключи нужны только
для ИИ-выводов. При первом открытии обзора или конкретного профиля запрос
запускается автоматически, если для этих данных ещё нет вывода. После сбоя
можно повторить запрос, а готовый вывод — обновить. Для официальных хостов
GigaChat приложение использует корневой сертификат из `llm/gigachat-root-ca.crt`.
Сертификат загружен по официальной ссылке из [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates).
При собственной конфигурации можно указать путь к другому PEM-файлу в `LLM_CA_FILE`.

Провайдер получает подготовленные факты по числовым оценкам: источник,
первый и последний доступные месяцы, значения и число ответов. В интерфейсе
эти данные остаются видимыми при отключённой модели. Свободные комментарии
и идентификаторы остаются на локальном сервере веб-дашборда.
Локальный процесс выполняет запросы к модели по очереди и кэширует выводы до перезапуска. После
изменения данных опроса или настроек модели прежний вывод больше не выдаётся за
актуальный для нового набора данных.

## Цветовые акценты

Оценки до 2 баллов отмечены красным, выше 2 и ниже 4 — янтарным, от 4 —
зелёным. Отдельно показываются пропущенные анкеты, снижение оценки на балл
и более, разница от двух баллов по близким вопросам двух источников и темы,
встречавшиеся в комментариях в нескольких месяцах. Темы определяются
локально по фразам и служат подсказкой для чтения первичных комментариев.
Связанные вопросы анкеты стажера и наставника подписаны отдельно.

## Подключение Google Forms

При обычном запуске FastAPI автоматически читает CSV-экспорт двух вкладок
Google Sheets и объединяет его с историей из Excel.

- Стажёры, `gid=720609798`. [Опрос стажёра](https://docs.google.com/forms/d/1CpknOK2OgjX0es_k6jxorI91vXZHLiCBVXxirXcqI7I/viewform)
- Наставники, `gid=1575164264`. [Опрос наставника](https://docs.google.com/forms/d/e/1FAIpQLScXMMmZZiKpMhpGZKhinOhdri-jPie2FUKDbxAvjdZeOaf9Lg/viewform)

Первая корректная анкета с новым ID создаёт профиль и задаёт подразделение.
Введите присвоенный стажёру ID, например `СТ-006`, и номер месяца от 1 до 6.
Импорт принимает «1», «Месяц 1» и «1-й месяц». Для одного ID
сохраняется до шести контрольных точек. Последняя корректная строка для
стажёра и месяца имеет приоритет над предыдущими ответами и Excel.
Строки с ошибками пропускаются, а их номера появляются в статусе
источника. Исходные книги остаются без изменений.

Оценка наставника связывается с профилем по ID стажёра и контрольному
месяцу. Для одного стажёра за месяц можно сохранить ответы нескольких
наставников. При повторной отправке того же наставника используется
последний корректный ответ. Если профиль ещё не создан, ответ наставника
появится после первой корректной анкеты самого стажёра.

В обзоре сводные карточки удовлетворённости и развития учитывают последнюю
оценку каждого стажёра. Графики и таблица показывают данные по каждому
месяцу отдельно. В боковой панели сначала видны пять последних добавленных
профилей. Остальные открываются кнопкой «Все стажёры».

В открытой вкладке дашборд проверяет версию каждые 15 секунд. Сервер
проверяет Google не чаще раза в 15 секунд. Когда появляются новые данные,
открытый обзор или профиль обновляется автоматически. При открытом чате
дашборд сообщает об обновлении и сохраняет диалог. Кнопка
«Обновить данные» сразу проверяет текущую версию. При сбое одной вкладки
другая продолжает обновляться. Для недоступной вкладки сервер использует
последние успешно полученные ответы в текущем процессе. При запуске без
доступа к Google отображается история Excel.

Чтобы запустить приложение только с Excel, задайте пустые значения
`MGTS_GOOGLE_INTERN_SHEET_ID` и `MGTS_GOOGLE_MENTOR_SHEET_ID` в окружении серверного процесса.

### Доступ к закрытой таблице

Действующие вкладки экспортируются по ссылке без входа в Google. Для
закрытого доступа включите Google Sheets API в облачном проекте служебного
аккаунта и предоставьте этому аккаунту доступ на чтение к таблице.
Настройте сервер и перезапустите его.

```bash
.venv/bin/python -m pip install -r backend/requirements-google.txt
export GOOGLE_APPLICATION_CREDENTIALS="/путь/к/ключу-служебного-аккаунта.json"
export MGTS_GOOGLE_INTERN_PRIVATE=1
export MGTS_GOOGLE_MENTOR_PRIVATE=1
```

Для своей таблицы задайте `MGTS_GOOGLE_INTERN_SHEET_ID` или
`MGTS_GOOGLE_MENTOR_SHEET_ID` и соответствующий параметр `_GID` либо
`_TAB` с названием вкладки. Ключ храните вне репозитория.

[Связь формы с таблицей ответов](https://support.google.com/docs/answer/2917686) ·
[Чтение диапазона Sheets API](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get)

## Проверка Excel

Загрузчик проверяет колонки, ID, номер месяца от 1 до 6, диапазоны оценок
и дубли. Повторная анкета определяется по стажёру и месяцу, для опроса
наставников также учитывается ID наставника. Пустые оценки допустимы.
При ошибке дашборд выводит имя книги и номер строки, если он известен.

## Проверки

```bash
.venv/bin/python -m pytest backend/tests frontend/tests -q
node --check frontend/web/assets/dashboard.js
```

Тесты API выполняются без реальных запросов к модели.

## Браузерные проверки

Для браузерных тестов понадобятся Node.js 22+ и Python-окружение из
[инструкции запуска](../README.md). Выполните из корня проекта:

```bash
npm ci --prefix frontend/tests/browser
npm exec --prefix frontend/tests/browser -- playwright install chromium
npm test --prefix frontend/tests/browser
```

Тесты сами запускают FastAPI на свободном локальном порту. Вместо GigaChat
используется тестовый ответ, поэтому ключ и доступ к провайдеру не нужны.
Можно задать пути к Python и Chromium в переменных `MGTS_TEST_PYTHON` и
`MGTS_TEST_CHROMIUM`. Проверки охватывают навигацию с клавиатуры, размеры
экрана от 320 до 1440 px, правила доступности axe и работу таблиц при сбое
загрузки графиков.

## Сценарии для короткой проверки с рекрутерами

Используйте демонстрационные анкеты. Предложите каждому участнику три задачи
без объяснения навигации:

1. Опишите, как изменился прогресс программы и на чьих оценках основан вывод.
2. Откройте стажёра со страницы обзора и найдите свежий отзыв наставника.
3. Выберите одно утверждение из ИИ-вывода и проверьте его по исходным цифрам.

Запишите, какие задачи выполнены без подсказки, сколько времени потребовалось
и в каких местах участник перепутал период или источник оценки. Сравните эти
наблюдения после следующей правки интерфейса.

## ИИ-помощник

Чат находится в правой колонке обзора и профиля. На телефоне доступна кнопка
«ИИ-помощник». Помощник использует область открытой страницы и версию опросов.
Диалоги живут в памяти вкладки и разделены между обзором и профилями.

Помощник отвечает на поддерживаемые вопросы об оценках, динамике, числе
ответов и локальных комментариях. FastAPI вычисляет факты и возвращает
ссылки на соответствующие строки таблицы. Для общих сводок GigaChat может
упорядочить факты, а сервер проверяет его выбор. При недоступной модели
показывается исходный порядок. В GigaChat отправляются только необходимые
числовые факты и названия показателей. Введённые вопросы, идентификаторы
и комментарии не пересылаются провайдеру.

Эндпоинты — `POST /api/assistant/overview` и
`POST /api/interns/{id}/assistant`. Тело содержит `question`, `version`
и необязательный `metric` для уточнений в текущем диалоге.
